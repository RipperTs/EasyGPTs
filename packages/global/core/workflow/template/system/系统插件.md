## 文本内容提取插件示例（ContextExtractModule）

### 1. 模板层：定义节点长什么样

文件：`packages/global/core/workflow/template/system/contextExtract/index.ts`

核心导出：

```ts
export const ContextExtractModule: FlowNodeTemplateType = {
  id: FlowNodeTypeEnum.contentExtract,          // 节点类型枚举
  templateType: FlowNodeTemplateTypeEnum.ai,    // AI 类型节点
  flowNodeType: FlowNodeTypeEnum.contentExtract,
  sourceHandle: getHandleConfig(true, true, true, true),
  targetHandle: getHandleConfig(true, true, true, true),
  avatar: 'core/workflow/template/extractJson',
  name: i18nT('workflow:text_content_extraction'),
  intro: i18nT('workflow:intro_text_content_extraction'),
  showStatus: true,
  isTool: true,                                 // 标记为可用作工具
  version: '481',
  inputs: [ ... ],
  outputs: [ ... ]
};
```

#### 1.1 输入定义（inputs）

- 选择模型：复用 `Input_Template_SelectAIModel`，并通过 `llmModelType: LLMModelTypeEnum.extractFields` 限制只展示支持「字段抽取」的模型。
- 抽取说明 `description`：文本区域，可填「希望抽取哪些信息、格式要求」等，最终会进入提示词。
- 历史轮次 `history`：复用 `Input_Template_History`，控制带入多少轮上下文。
- 待抽取文本 `contextExtractInput`：
  - `renderTypeList: [reference, textarea]`，可引用上游节点输出，也可直接输入。
  - 必填，`valueType: string`。
- 字段配置 `extractKeys`：
  - `renderTypeList: [custom]`，使用自定义输入组件配置要抽取的字段。
  - 默认值为空数组。

字段配置的类型定义在：

```ts
// packages/global/core/workflow/template/system/contextExtract/type.d.ts
export type ContextExtractAgentItemType = {
  valueType: WorkflowIOValueTypeEnum.string | number | boolean;
  desc: string;          // 字段说明
  key: string;           // 字段 key
  required: boolean;     // 是否必填
  defaultValue?: string; // 默认值
  enum?: string;         // 多行字符串，每行一个枚举值
};
```

#### 1.2 输出定义（outputs）

```ts
outputs: [
  {
    id: NodeOutputKeyEnum.success,
    key: NodeOutputKeyEnum.success,
    label: i18nT('workflow:full_field_extraction'),
    valueType: WorkflowIOValueTypeEnum.boolean
  },
  {
    id: NodeOutputKeyEnum.contextExtractFields,
    key: NodeOutputKeyEnum.contextExtractFields,
    label: i18nT('workflow:complete_extraction_result'),
    valueType: WorkflowIOValueTypeEnum.string
  }
];
```

- `success`：是否抽取成功（字段完整且没有多余字段）。
- `contextExtractFields`：抽取结果整体的 JSON 字符串。
- 运行层会把 `arg` 中的每个字段也展开成独立输出（例如 `orderId`、`amount`），用于后续节点引用。

### 2. 运行层：节点实际如何执行

文件：`packages/service/core/workflow/dispatch/agent/extract.ts`

入口函数：

```ts
export async function dispatchContentExtract(props: Props): Promise<Response> {
  const {
    user,
    node: { name },
    histories,
    params: { content, history = 6, model, description, extractKeys }
  } = props;
  ...
}
```

`params` 对应模板层的 inputs：

- `content` → `NodeInputKeyEnum.contextExtractInput`
- `history` → `NodeInputKeyEnum.history`
- `model` → `NodeInputKeyEnum.aiModel`
- `description` → 抽取说明
- `extractKeys` → 字段配置数组

#### 2.1 基本流程

1. 校验输入：
   - `content` 为空直接报错；
   - 根据 `model` 查找 `extractModel`，不存在则报错。
2. 处理上下文：
   - 使用 `getHistories(history, histories)` 获取指定轮数的历史对话。
3. 根据模型能力选择调用方式：
   - 如果模型支持 `toolChoice` → 走 `toolChoice`（新版 tools）。
   - 否则如果支持 `functionCall` → 走 `functionCall`（旧版函数调用）。
   - 否则 → 走 `completions`（纯 prompt 输出 JSON）。
4. 基于 `extractKeys` 构造 JSON Schema 或提示词：
   - `type` / `description` / `enum` 等信息全部由前端配置传入。
5. 调用大模型，拿到字段 JSON（`arg`）和 tokens。
6. 对 `arg` 做校验与修正，最终计算 `success` 并返回。

#### 2.2 三种调用模式的核心写法

公共 schema 构造（简化）：

```ts
const properties: Record<string, { type: string; description: string }> = {};
extractKeys.forEach((item) => {
  properties[item.key] = {
    type: item.valueType || 'string',
    description: item.desc,
    ...(item.enum ? { enum: item.enum.split('\n') } : {})
  };
});

const agentFunction = {
  name: agentFunName,
  description: '需要执行的函数',
  parameters: {
    type: 'object',
    properties,
    required: []
  }
};
```

1）`toolChoice`（新 tools）：

```ts
const tools: ChatCompletionTool[] = [{ type: 'function', function: agentFunction }];
const response = await ai.chat.completions.create({
  model: extractModel.model,
  temperature: 0.01,
  messages: filterMessages,
  tools,
  tool_choice: { type: 'function', function: { name: agentFunName } }
});

const arg = json5.parse(
  response?.choices?.[0]?.message?.tool_calls?.[0]?.function?.arguments || '{}'
);
```

2）`functionCall`（旧版函数调用）：

```ts
const functions: ChatCompletionCreateParams.Function[] = [agentFunction];
const response = await ai.chat.completions.create({
  model: extractModel.model,
  temperature: 0.01,
  messages: filterMessages,
  function_call: { name: agentFunName },
  functions
});

const arg = JSON.parse(
  response?.choices?.[0]?.message?.function_call?.arguments || ''
);
```

3）`completions`（纯文本 + JSON 提示）：

```ts
const messages: ChatItemType[] = [
  {
    obj: ChatRoleEnum.Human,
    value: [{
      type: ChatItemValueTypeEnum.text,
      text: {
        content: replaceVariable(
          extractModel.customExtractPrompt || Prompt_ExtractJson,
          { description, json: ..., text: ... }
        )
      }
    }]
  }
];

const data = await ai.chat.completions.create({
  model: extractModel.model,
  temperature: 0.01,
  messages: requestMessages,
  stream: false
});

const answer = data.choices?.[0].message?.content || '';
const jsonStr = sliceJsonStr(answer);      // 从回复中截取 JSON 段
const arg = json5.parse(jsonStr || '{}');  // 容错解析
```

#### 2.3 字段校验与补全

```ts
// 删除多余或空字符串字段
for (let key in arg) {
  const item = extractKeys.find((item) => item.key === key);
  if (!item || arg[key] === '') {
    delete arg[key];
  }
}

// 必填字段自动填充默认值
extractKeys.forEach((item) => {
  if (item.required && !arg[item.key]) {
    arg[item.key] = item.defaultValue || '';
  }
});

// success 判定：字段既不少也不多
let success = !extractKeys.find((item) => !(item.key in arg));
if (success) {
  for (const key in arg) {
    const item = extractKeys.find((item) => item.key === key);
    if (!item) {
      success = false;
      break;
    }
  }
}
```

#### 2.4 组装输出与计费

```ts
const { totalPoints, modelName } = formatModelChars2Points({
  model: extractModel.model,
  tokens,
  modelType: ModelTypeEnum.llm
});

return {
  [NodeOutputKeyEnum.success]: success,
  [NodeOutputKeyEnum.contextExtractFields]: JSON.stringify(arg),
  ...arg,
  [DispatchNodeResponseKeyEnum.nodeResponse]: {
    totalPoints: user.openaiAccount?.key ? 0 : totalPoints,
    model: modelName,
    query: content,
    tokens,
    extractDescription: description,
    extractResult: arg,
    contextTotalLen: chatHistories.length + 2
  },
  [DispatchNodeResponseKeyEnum.nodeDispatchUsages]: [
    {
      moduleName: name,
      totalPoints: user.openaiAccount?.key ? 0 : totalPoints,
      model: modelName,
      tokens
    }
  ]
};
```

- 对外输出：
  - `success`、`contextExtractFields`；
  - 以及 `arg` 中的每个字段（铺到返回对象上）。
- 内部统计：
  - `nodeResponse`：用于调试和记录抽取详情；
  - `nodeDispatchUsages`：用于计费统计。

### 4. 按此示例开发新的系统基础插件的推荐步骤

1. 在 `FlowNodeTypeEnum` 中增加新的节点类型枚举值。
2. 在 `constants.ts` 中为该节点补充输入/输出的 `NodeInputKeyEnum`、`NodeOutputKeyEnum`。
3. 在 `template/system/xxx/index.ts` 中定义节点模板：
   - 填写 `id`、`flowNodeType`、`inputs`、`outputs`，必要时设置 `isTool`、`templateType` 等。
4. 在 `template/constants.ts` 的 `systemNodes` 中注册该模板。
5. 在 `service/core/workflow/dispatch/...` 中实现 `dispatchXxx`：
   - 从 `props.params` 读取输入，调用实际能力（AI / HTTP / 本地逻辑），组装输出。
6. 在 `dispatch/index.ts` 的 `callbackMap` 中将 `FlowNodeTypeEnum.xxx` 映射到 `dispatchXxx`。

这样即可完成一个系统基础插件从「可视化节点模板」到「后端真实能力」的完整接入。
